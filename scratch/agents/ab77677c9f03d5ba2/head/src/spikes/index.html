Hardware spikes

Open each page on the device you are testing, let it run for a few seconds, then use Copy results and paste the JSON back. Every timing is a rolling 60-frame average with p95: CPU is the JavaScript time to update and draw a frame, frame interval is the gap between frames, and GPU is the draw time when the browser can measure it.

  • Spike 1: fill rate. 30,000 motes drawn as large halos at the worst camera framing. Add ?n= and ?dpr= to vary them. The GPU frame time on a recent iPhone and a 2023 mid-range Android decides the DPR cap and the per-tier halo pixel cap.
  • Spike 2: vertex cost. 100,000 motes with every fault and the drift field on, on an integrated-GPU laptop. Add ?isolate=1 to measure mostly vertex work. Vertex time above about 4 ms means the optional position pass is needed.
  • Spike 3: float texture read. A vertex shader reads an RGBA32F texture on iOS Safari. PASS keeps float transform storage; FAIL means a different transform format.
  • Spike 5: point size limits. Records the aliased point size range and the other limits on each test device. A small maximum point size confirms that motes are quads.
